# 项目、多源文件夹与本机自动连接

日期：2026-09-18。此文记录本次实现，替代旧设计中“手动配对为主入口、一个工作空间对应一个目录、下拉切换单个工作空间”的产品交互。

## 功能与交互

主侧栏采用“项目 → 会话”的分组层级，所有已添加项目同时显示，组内显示会话时间与标题。用户可折叠项目、点击项目标题选择其会话、点击 `＋` 新建会话、通过 `⋯` 修改项目名称和源文件夹。归档模式按项目显示已归档会话。

新建会话立即持久化，不再等待第一条消息；默认标题为“新会话”，第一条非空文本提交后生成最多 48 字的标题。存在多个 Agent 时，可在侧栏“新会话使用”中选择后再新建，已创建会话的 Agent 保持绑定。浏览器本地仅保存上次项目/会话 ID，不保存启动凭证。会话各自具有分支与运行记录，同项目的会话共享真实文件。

创建/编辑项目的表单支持多个目录条目、系统选择、手动填写和移除关联。第一个目录是相对路径与默认进程工作目录的基准。增加其他目录不会复制源文件，移除关联也不删除文件。不同项目可引用同一目录，这表示有意共享文件；同一项目内按规范化路径去重。源文件夹列表不能为空。

参考：Codex 的项目与会话组织方式及 [官方功能文档](https://learn.chatgpt.com/docs/features)。本产品的“一个项目多个源文件夹”是本次用户要求，不宣称与 Codex 的目录实现相同。

## 数据与兼容性

- 原 `workspaces` 表的 ID 继续作为项目 ID，`root` 继续保存第一源目录。
- `records` 的 `project_roots` namespace 保存 `{roots: [...]}`，读取旧数据时缺省为 `[root]`，无需破坏性数据库迁移。
- 会话及执行契约保留内部 `workspace_id` 字段，指向项目；防止更名破坏历史运行、产物、工具账本和 checkpoint 引用。
- 项目更新与 roots 写入处于同一 SQLite 事务；`expected_revision` 防止覆盖并发修改。存在非终态运行时返回 `PROJECT_BUSY`，避免运行/审批期间改变授权范围。
- SQLite 原有备份包含新增 roots 记录。旧版本不了解多个目录，完整使用多目录项目必须运行此版本。

## HTTP 契约

| 接口 | 用途 |
| --- | --- |
| `GET /api/projects` | 分页列出项目，包含兼容的 `root` 与完整 `roots` |
| `POST /api/projects` | `{name, roots}`，创建项目 |
| `PATCH /api/projects/{id}` | `{name, roots, expected_revision}`，更新项目 |
| `POST /api/local/folder-picker` | 在本机桌面打开目录窗口，返回 `{path, cancelled}` |
| `/api/sessions?workspace_id=...` | 原会话协议，按项目筛选 |

旧 `/api/workspaces` 接口继续兼容单目录客户端。新项目写接口继承认证、Origin、CSRF 和幂等键。前端遍历所有分页，避免较早项目或会话被固定页长隐藏。

## 多目录执行与权限

`Store.workspace()` 统一返回 roots；PolicyEngine 在真实解析后的目录集合中判断包含关系，并保留原链接/reparse/备用数据流检查。写入不能覆盖任一根目录。文件工具为所访问的根目录持有 Windows directory guards，第二目录的结果使用绝对路径以避免同名歧义。MCP 配置的 cwd 也可位于任一项目根下。

运行配置快照记录 `project_roots`；模型系统上下文列出源文件夹，并明确第一目录/绝对路径语义。名称视为数据。相对路径搜索仍只遍历默认目录；跨目录搜索需分别指定各根路径。命令执行仍是经审批的可信本机执行，不是操作系统沙箱。

## 自动连接

`harness serve --open` 等服务 ready 后，使用实际运行实例的 Host/Port 打开浏览器；启动脚本默认调用该命令。CLI 在本机数据库创建 60 秒一次性 ticket，放入 URL fragment，服务器访问日志不接收 fragment，CLI 不输出完整地址或 ticket。前端读出后立即通过 `history.replaceState` 清除，再交换原有 HttpOnly/SameSite=Strict Cookie；StrictMode 并发挂载共享一次交换。

登录有效期维持 24 小时，已有 Cookie 刷新时直接恢复；重新运行启动入口可重新自动连接。手动 `harness pair` 保留 5 分钟有效的一次性口令作为备用。凭证失效时页面引导重启入口或备用连接，不开放匿名项目 API。URL fragment 在页面读取前仍短暂存在于浏览器，本方案不宣称对同用户恶意进程提供隔离。

## 原生目录窗口

Windows 上通过独立 PowerShell STA 子进程调用系统 FolderBrowserDialog。脚本内容固定，不插入用户输入；目录结果以 UTF-8/Base64 传回 API。API 将阻塞工作移至线程，不阻塞事件循环；同进程只允许一个窗口，180 秒超时。用户取消返回空选择，页面保留原内容。非 Windows 或缺少可交互桌面时使用手填路径。

## 验收范围

自动测试覆盖：旧项目读取和重开数据库、两个目录、多个会话和跨项目筛选、修改版本冲突、运行中修改拦截、第二目录列举/搜索/读取、越界与根目录保护、目录选择成功/取消的接口处理、匿名/跨站拒绝、自动启动 URL 与 ticket 单次使用、前端分页和 StrictMode 交换。

浏览器与最终构建的实际结果记录在 `docs/verification/projects-acceptance.md`；测试用 Mock 目录选择不等同于真实系统窗口验收。

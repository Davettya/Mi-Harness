# 12 · 工程基础、权限策略与本地服务生命周期

前置阅读：[01 公共契约](01-contracts.md)、[02 存储与一致性](02-storage.md)。

关联模块：[03 模型](03-model-gateway.md)、[06 调度](06-scheduler.md)、[07 工具](07-tools.md)、[08 扩展](08-skills-plugins.md)、[10 API](10-api-events.md)、[13 验证](13-verification.md)。

本文负责工程启动条件、身份与权限权威、凭据与出站策略，以及本地 supervisor 的生命周期协调。P0 范围为 Windows 单用户服务、API 与 worker 双进程、SQLite。

## 1. 唯一职责与边界

- 提供可重复安装的依赖锁、目录约定、配置加载和服务入口。
- PolicyEngine 唯一负责计算有效权限、审批要求和授权范围，向执行模块提供可验证授权。
- 提供用户配对、会话鉴权、凭据引用解析及统一出站决策。
- supervisor 负责服务身份、端口、子服务启动停止和更新协调。
- 02 负责备份一致性、数据库迁移和恢复算法；本文只描述调用顺序与失败处理。
- 07 负责具体工具命令的 OS 进程树；supervisor 不重复实现工具执行器。
- API 路由、请求响应和 SSE 协议归 10；扩展 manifest 与兼容检查归 08。

## 3. 第一步：工程初始化与版本锁定

1. 记录支持的 Python、Node、Windows 版本与安装方式，将“拟支持”和“已实测”分开。
2. 按原设计选择 FastAPI、React、LangChain create_agent 与 LangGraph，建立最小可安装骨架。
3. 为 LangChain、LangGraph、MCP adapter、FastMCP 和 provider 包生成精确依赖锁。
4. 把官方发布状态与本项目实际锁定版本写入兼容记录；不能直接把调研日期当作安装版本。
5. 前后端各保留一个权威锁文件，CI 使用冻结安装；依赖更新通过独立变更执行兼容验证。
6. 为 API、worker 与 CLI 提供不同入口，但复用同一配置解析、领域契约和日志过滤模块。
7. 使用假模型和空工具完成一次本地服务启动，随后再接入 03/05 的真实运行能力。

阶段零要实测 interrupt 重放、checkpoint 恢复、MCP 选定协议与 Windows 进程树管理；未通过时记录阻塞，不以接口存在代替能力通过。

## 4. 第二步：配置层级与运行快照

拟议优先级从低到高为：内置默认值 → 用户配置 → 工作区配置 → 进程环境覆盖 → 显式 CLI 参数。

权限配置与普通偏好分开合并：低信任层只能收缩权限，不能因层级更高而覆盖管理员限制；环境变量只接受白名单键。

1. 每层先按 schema 校验，再归一化路径、模型引用、超时和配额单位。
2. 输出解释型配置结果：有效值、来源层、被拒绝覆盖项与原因。
3. 凭据项只允许引用，不接受写入普通配置文件的明文密钥。
4. run 启动时生成可追溯配置快照，关联模型、Agent、工具及扩展版本 hash。
5. 活跃 run 使用其快照；安全策略撤销仍实时生效，配置快照不能恢复已撤销权限。
6. 端口和数据目录修改要求重新启动；运行期支持热更新的字段必须单独列出。

相对路径按对应配置文件所在位置解析，写入快照时保存解析结果和原始来源，防止启动 cwd 改变其含义。

实现约定：启动器将解析后的完整有效配置（只含凭据引用）按实例写入数据目录；supervisor 获得目录锁后发布 `system/effective_config`，API 与 Worker 按 instance_id 校验并读取同一配置，禁止分别退回默认值。doctor 区分调用端解析配置与运行实例配置。当前 CLI 配置字段统一需重启；模型/Agent 管理 API 的版本更新只影响新 run。

平台 `permissions` 是通用能力上界，默认 `network=false`、`process=false`、`workspace_write=true`；用户级受信任配置可明确启用，工作区、环境或 CLI 不能扩大上界。该默认允许演示模型、本地只读及需审批的工作区写入。HTTP MCP 与 stdio MCP 分别需要启用 network 或 process；模型页显式选择的单个模型端点采用本文件 §7 的专用授权，不修改通用权限。全局/工作区 UI 策略中的允许能力须再与平台上界求交，工具审批不能越过上界。network=false 拒绝没有专用授权的网络诊断，process=false 拒绝 stdio 诊断启动。allowed_hosts 为空表示不追加主机列表限制；低信任层可从空列表收窄至显式列表，不能清空已有受限列表。

`model_profile_ref` 覆盖内置 default Agent 的新 run 默认模型，显式其他 Agent 模板保留自己的模型策略；运行快照固定解析后的引用。日志等级在 API/Worker 启动时使用。权限上界变更递增持久策略版本，恢复任务不能利用旧快照扩大权限。

AgentSpec.policy 引用 `config/policies` 中的命名策略，并与全局、工作区、平台权限求交；审批要求取并集，出站限制取更严格者。快照保存解析结果，执行时继续与该命名策略的当前状态收窄；删除或撤销策略不能回退成默认允许。当前上下文仅提供内置 default 策略，并将完整 ContextPolicy 写入快照；未知 context_policy 在配置保存与run提交时明确拒绝。

## 5. 第三步：PolicyEngine 与授权契约

有效权限按用户授权、工作区策略、Agent 能力、工具约束、当前执行环境限制求交；子 Agent 还必须受父权限上界限制。

模块私有 `PolicyDecision` 只返回允许、拒绝或需要审批，以及理由、可授权资源集合和策略版本。

模块私有 `ExecutionGrant` 包含授权 ID、公共 ApprovalBinding 引用、主体与 run 归属、剩余使用次数和撤销状态；参数与资源绑定直接使用 01 的 ApprovalBinding，不再定义第二套字段。

1. 请求先验证主体和会话，再读取服务器持有的能力配置；忽略模型自称的身份或权限。
2. 解析实际资源并计算权限交集，再决定允许、拒绝或生成待审批请求。
3. 审批内容使用用户能理解的操作、目标和副作用；展示内容与授权参数摘要必须来自同一规范化请求。
4. 审批记录由 05 持久化交互关联；审批通过后再创建 grant，不能把审批 UI 打开视为授权。
5. 07 在资源锁内消费 grant；消费操作与 operation 进入 running 的条件更新通过 02 原子执行。
6. 消费时重新检查到期、撤销、参数漂移、主体及当前策略；拒绝重放已消费的一次性授权。
7. run 取消、会话撤销或策略收缩时撤销相关 grant；执行中的不可撤销外部动作转核对流程。

Skills、网页内容、MCP annotations 和 Agent 提示词均不能修改 PolicyEngine 的配置，也不能自行签发 grant。

模型/MCP诊断采用 01 DiagnosticContext 的单独能力集合：只允许已配置目标、固定测试项及有限资源；凭据与出站检查复用本模块。该身份不得获得工具 ExecutionGrant、工作区写入、任意进程启动或Agent委派权限。已配置stdio服务的启动按专用连接用途审核并受监督，不能将其配置参数当作诊断请求的自由命令输入。

## 6. 第四步：本地 Web 身份与会话

默认只监听 loopback，API 与静态资源同源；绑定地址、Host 白名单与 Origin 白名单分别校验。

1. 首次启动生成短期一次性配对口令，通过本地受控入口展示，禁止写入常规日志或放入 URL。
2. 配对成功后签发 HttpOnly、SameSite 的会话 cookie；会话需有到期、撤销和重新配对流程。
3. HTTPS 部署启用 Secure；纯 loopback 开发模式的差异写入部署配置，不能自动放宽到局域网。
4. 写接口实施 CSRF 防护，CORS 使用精确列表；这些检查由 10 的统一中间件调用本模块能力。
5. worker 与 API 的内部信任边界使用本机受限通道和服务身份，不能接受浏览器直接调用 worker。
6. 局域网访问是单独启用的部署模式，需 TLS、身份与设备管理；P0 不默认开放。

日志记录鉴权结果与主体引用，不记录配对口令、cookie、Authorization 或原始凭据。

## 7. 第五步：凭据与数据出站

凭据保存在 Windows 凭据库或经过验证的等效加密存储；业务表、配置和 checkpoint 只保存可撤销引用。

2026-09-17 修订：模型页允许已配对用户通过同源敏感配置端点输入 API Key；入站密钥仅短时存在内存，保存成功后写入系统凭据库，普通配置仍只存引用。旧凭据不回传页面，轮换时创建新引用以保留旧 run 的固定配置；失败清理本次新建的凭据，不删旧引用。

模型页的显式发现/测试/保存动作可授权所选模型的精确服务地址：临时诊断授权绑定 owner、diagnostic_id 与完整规范化 base URL，保存后的授权另绑定不可变 profile ref。该专用授权仅用于 model 目的，可满足默认关闭通用网络时的模型连接需求；不开放网页工具、MCP 或进程。仍应用当前及快照的 local_only、域名上限、私网/元数据拒绝和凭据目标匹配，不能绕过这些约束。通用配置 PUT 不产生此授权；修改地址须重新输入 Key、检查并授权，HTTP 重定向不得携带 Key 自动跟随。

- 凭据解析发生在实际调用边界，只向指定模型客户端、MCP 客户端或子进程传入所需项。
- 环境变量采用允许列表，从空白或最小基础环境构建；不复制 Host 的完整环境。
- 统一过滤日志、异常、HTTP 调试、导出和 tracing 中的敏感字段；过滤失败时停止记录该内容。
- 禁止把解密密钥或完整客户端对象序列化进 ExecutionContext 的持久化部分。

工作区出站模式采用 `cloud_allowed`、`local_only` 或显式域名允许列表，由各调用入口请求同一 PolicyEngine 决策。

1. 建立调用目标清单，覆盖主模型、摘要、嵌入、搜索、遥测与远程 MCP。
2. local_only 对清单所有项目生效；摘要或检索降级不能绕过它。
3. 本地模型与本地 MCP 由管理员配置为专用端点，只授权给相应客户端用途。
4. 通用 fetch 校验域名、解析 IP、重定向及实际连接目标，默认阻止私网、loopback 和云元数据地址。
5. 对代理路径无法核验目标的请求拒绝执行，避免批准域名后通过代理访问未批准地址。
   官方模型 HTTPS 端点的 Fake-IP 兼容例外：仅在精确模型授权有效、完整 base URL 与内置官方目录一致，且所有非公网解析结果均属于 IPv4 `198.18.0.0/15` 时允许继续连接。连接仍按原始官方主机名验证 TLS 证书，禁止重定向和环境代理；不允许用户关闭证书校验。此例外不适用于 HTTP、任意自定义端点、MCP 或网络工具，也不绕过 local_only、域名/平台主机限制。私网、元数据、其他保留地址或混合解析仍拒绝。
6. 策略决定、目标类别和数据分类可审计；不在审计记录中复制完整用户内容。

路径授权同样由本模块决定：规范化并处理 Windows 大小写、UNC、设备路径、符号链接和 reparse points；07 在访问瞬间执行资源复查。

产物内容策略同样集中在此：下载使用正确MIME与Content-Disposition，Markdown默认禁止原始HTML执行并过滤危险URL；HTML/SVG等主动内容在sandbox iframe或隔离origin显示，不携带Host凭据、不开放Host API。11实现具体渲染组件，10应用响应头与访问检查，均不改变这一边界。

## 8. 第六步：supervisor 启动和停止

拟议 CLI 为 `harness serve/status/stop/doctor`，其安装及参数在实现后生成帮助与发行说明。

1. 获取数据目录实例锁，核对 PID、进程启动时间、实例身份和监听地址。
2. 若存在同一服务实例，返回其可信状态与入口；端口属于其他应用时明确报错。
3. 初始化配置、日志、凭据可用性和 02 的存储健康检查，再依次启动 API 与 worker。
4. 双进程使用同一实例标识；启动失败时只清理本次创建且身份匹配的进程。
5. status 区分 API 存活、worker 可领取、数据库可写与恢复待核对，不能只测端口开放。
6. stop 先停止新领取，再请求 06 排空或安全暂停，等待 07 处理具体工具进程，然后关闭服务。
7. doctor 输出可分享的脱敏诊断，不自动清空队列、删除数据或终止无关进程。

Windows 上原子状态文件的读写遇到短暂共享占用时，最多重试 2 秒。写入超时保留上一个原子快照；读取持续失败返回 `INSTANCE_STATE_UNAVAILABLE`，不能误报为已停止或据此启动重复实例。

系统退出和更新中断都保留未结 run 与 operation，重启后由 06/07 执行恢复判断。

## 9. 更新、备份和恢复协调

更新协调顺序为：禁止新任务与配置写入 → 排空或安全暂停 → 确认所有业务/checkpoint写者停止并冻结GC → 调用 02 一致性备份 → 迁移 → 启动新版本 → 健康与兼容验证。维护期间可保留只读诊断入口。

备份内容、checkpoint 对齐、manifest 和恢复完整性校验只按 02 实施，不在本模块另写数据库文件复制方案。

- 备份或排空失败时停止更新，保留原版本服务与可解释状态。
- 新版本启动失败时先判断旧程序是否兼容新 schema，再决定运行时回退或数据恢复。
- 需要恢复匹配备份时保留迁移后数据副本；无法安全回退则进入只读恢复模式。
- 恢复应用数据不会撤销工作区修改或外部服务操作，06/07 继续核对相关副作用。
- 卸载与更新只操作声明的安装目录，用户工作区和用户数据保留策略需显式配置。

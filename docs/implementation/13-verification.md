# 13 · 观测、验证与发布门槛

[实现入口](README.md) · 本文件是实现指导中测试定义、验收条件和观测交付的唯一来源

本文件维护测试定义；当前执行结果与功能核对见 [14 · 开发实施计划](14-delivery-plan.md) 和 `docs/verification/`。模块文档只引用编号；调整测试场景在此处修改，不在各模块维护另一张验收表。

## 1. 测试分层与证据

| 层次 | 建议位置 | 使用数据 | 目的 |
|---|---|---|---|
| 契约/模块测试 | `tests/contract/`、`tests/unit/` | 固定 DTO 与边界数据 | 类型、序列化、校验、模块算法 |
| 故障恢复 | `tests/recovery/` | 假模型、可控工具/MCP server、临时库 | 定位持久化边界与重放风险 |
| 安全边界 | `tests/security_boundaries/` | 专用 canary 密钥/目录/网络环境 | 权限、进程、跨域与敏感信息泄漏 |
| 产品 E2E | `tests/e2e/` | 临时工作区和浏览器 | 提交、审批、取消、重连及产物 |
| 真实兼容 | `docs/compatibility/` | 显式测试账号和指定服务 | 验证真实 adapter/model/server 组合 |
| 任务效果 | `evals/` | 固定版本的任务与评分规则 | 效果、成本和性能比较 |

每条结果记录：测试 ID、代码 revision、依赖 lock hash、OS/硬件、adapter/model/server/protocol、输入 fixture hash、实际断点、断言结果、trace/artifact 引用和时间。不得把安装成功、HTTP 可达或工具发现成功当作完整兼容通过。

测试使用临时数据目录与工作区；重启/强杀只针对被测试进程。真实外部写入使用隔离测试资源，不能让故障注入影响用户现有文件或业务账号。

## 8. 观测实现规范

身份字段引用 [01](01-contracts.md)，不另造不兼容 trace key。每个 root run 有 trace，model attempt、tool operation、压缩、MCP与child关联 span。日志记录阶段、耗时、错误类别和引用，默认不记全文内容或秘密。

分清三类输出：诊断日志服务开发者；耐久领域事件服务UI与审计；指标服务统计。相同底层事实可以投影到三者，但不能复制三套执行状态。事件内容见 [10](10-api-events.md)，秘密与远程观测授权见 [12](12-platform.md)。

必须提供指标：queue latency、模型首token与总时延、retry次数、usage已知/未知、预算预留、压缩触发与失败、tool失败分类、unknown operation数、checkpoint延迟、恢复候选/结果、取消后存活进程、outbox积压。

## 9. 性能与任务效果目标

以下为建议门槛，首次测量须记录基准机器，不代表已实现能力：

| 指标 | 初始目标 | 测量条件 |
|---|---|---|
| API受理 | P95 < 200 ms | 本地20个并发短请求，排除模型服务耗时 |
| 事件呈现 | P95 < 300 ms | 后端生成到浏览器渲染，固定负载 |
| 重启后状态解释 | 10秒内完成初始扫描 | queued/running/waiting各类固定样本 |
| 本地命令取消 | 2秒内发信号，5秒内确认可控进程树退出 | 允许升级终止；不可控情况明确报告 |
| 大工具输出 | 100MB fixture不撑爆内存与模型窗口 | 输出限额由工具配置提供 |
| 长时运行 | 8小时无孤儿进程或持续增长泄漏 | 重复会话切换与固定任务负载 |

任务集固定30～50个中文任务，覆盖研究、编辑、代码、工具查询、长上下文与恢复。记录完成率、引用正确率、产物可用性、约束遵守、耗时与费用。确定性结果程序校验，开放题人工评分；模型评价只能辅助。

## 10. 发布与回归

Fake-IP 兼容回归：六种官方 HTTPS 端点的临时诊断授权及已保存授权均可通过基准测试地址段；HTTP、非标准端口、非官方路径/查询、自定义主机、IP literal、MCP/fetch、无授权、混合私网/元数据/IPv6 地址仍拒绝。验证 local_only、域名限制、平台主机限制及撤销继续生效；实际网络探测不携带用户 Key，只检查 TLS 和到达认证层。

2026-09-17 模型简化配置修订增加 UI01/M01/SEC01/SEC02/DB01 的联合场景：从三个输入完成添加与保存使用，检查实际默认 Agent 引用；编辑留空保留旧 Key、轮换产生新引用、切换提供方不复用凭据；发现/测试失败不保存配置，保存失败/版本冲突不改变默认；Key 不出现在普通配置、命令记录、错误与浏览器缓存。未经配对、跨域与 CSRF 请求拒绝；维护期间不新增模型配置。精确模型授权只能连接指定 endpoint，不能被网页工具/MCP/另一 profile 使用，仍受 local_only/域名/SSRF 约束。在线供应商未配置时仅报告本地受控协议验收。

PF01 增加 Windows 状态文件共享占用故障注入：短暂读取失败后返回原子快照，持续读取失败明确报错且不启动新实例；同时重跑真实备份恢复后启动与后续任务流程。全量回归中发现的问题保留原失败记录，修复的针对性回归单独关联，不改写历史结果。

每次修改核心契约、provider、LangChain/LangGraph、saver、MCP或策略，运行影响到的契约测试与故障恢复用例；正式发布再运行本阶段全部E2E和任务基准。开发过程只改可逆低影响展示时按影响范围验证，不机械执行所有真实收费任务。

P0发布必须满足：测试矩阵P0项有结果，真实兼容清单列明支持组合，未实现能力可解释，安装/停止/备份/恢复验证完成，已知限制写入release notes。模拟测试通过不能替代真实供应商测试；外部依赖不可用时标为未验收，不能写成通过。

P1及以后只将已完成且通过对应门槛的模块暴露为可用功能。保留原P0回归；不能因加入多Agent而削弱单Agent恢复和权限行为。

设计来源：[原设计 §16](../通用Agent-Harness系统设计文档.md#s16)、[§18](../通用Agent-Harness系统设计文档.md#s18)；补充测试细化了原设计中的交互与故障窗口，没有引入新的产品范围。
